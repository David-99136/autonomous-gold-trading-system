# 交易期間精簡回報

僅控制已授權交易期間的對話，不授權下單、不啟動服務、不切換 Demo／Live，亦不更改風控或核准要求。遵循專案規格；開發、除錯及使用者主動詢問不受靜默規則限制。

## 何時回報

- 開單：券商已確認成交或接受掛單才回報。明確區分「已成交」與「掛單已接受」；掛單後成交屬新的狀態，可另報一次。加倉視為開單。
- 結束：已確認部分／全部平倉、撤單成功才回報。部分平倉須列剩餘數量，不能稱為全部結束。請求送出或 HTTP 成功不等於成交／撤單完成。
- 日結：依系統已設定的交易日與時區，每日一份摘要；不得自行選擇午夜作為交易日邊界。若邊界未設定，先確認，不宣稱日結排程已啟動。
- 安全例外：結果 UNKNOWN、無法確認保護停損、斷線影響持倉管理、熔斷、Recovery Locked、執行模式變更、減風險失敗或需要使用者授權時，立即簡短告警。新事件、嚴重度升級或需要新行動可再報；不得為省 token 隱藏問題。

例行行情、逐根 K 線、分析進度、NO_TRADE、成功心跳／登入／對帳、例行停損調整、一般拒單僅記錄本機，不逐筆推播。安全相關拒單仍立即告警。平台要求的進度更新維持最短必要內容，不宣稱能停用平台要求。

## 訊息格式

事件一至兩行，僅使用已核實資料：

- `[Demo 開單／已成交] 商品｜方向｜數量 @ 成交價｜停損／停利`
- `[Demo 開單／掛單已接受] 商品｜方向｜數量｜委託價｜停損／停利`
- `[Demo 部分平倉／全平倉／撤單成功] 商品｜數量｜成交價（適用時）｜已實現損益或待核對｜剩餘數量`
- `[風險告警] 問題｜已確認的處置／仍未知狀態｜需要使用者做什麼`

Demo、Paper 與 Live 必須如實標示，不能混用。省略問候、重複策略解釋、原始 JSON、帳戶識別碼及憑證。資料或費用未知寫「待核對／未量測」，不能補零。

## 日結與證據

用一段或最多六行呈現：交易日與時區／模式、完成交易數與勝負、已實現淨損益及費用完整性、最大浮虧與風控事件、剩餘部位／掛單、AI 用量與成本（可得時）、完整本機日報連結。零交易亦提供日結。完整日報保留專案要求的滑價、R 倍數、Profit Factor、拒單與 NO_TRADE 原因、版本及來源歸因；缺失欄位標示未知。

優先使用帳務程式的已核對聚合值，不讓模型從整份成交紀錄心算；部分平倉不能重複計為完整交易。浮盈不計已實現獲利，尚未核對的日報標示「暫結」，不得聲稱帳戶已清空。不得為產生日報額外逐筆重新登入。

沿用既有事件 ID／狀態版本及通知紀錄避免重複回報；無持久化通知紀錄時，只能保證本次上下文內去重，不聲稱跨重啟 exactly-once。完整稽核與逐筆成交核對照常，不因靜默省略。若未有背景服務／排程，明確說明無法僅靠此技能自動發送日結。

靜默不是多做模型呼叫後丟棄文字：有現成事件篩選器／模板就先篩選，再產生通知；不要只為敘述無變化狀態反覆叫模型。分析代理的結構化訊號、風控與執行頻率維持原設定。此技能不保證固定 token 節省比例，也不能證明使用者回覆是主要用量來源。
