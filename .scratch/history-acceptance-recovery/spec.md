## 2. 範圍與不變條件

- 保留兩侧 bid/ask、固定查詢窗口、首次價格指紋、point-in-time 可用時間。
- 不以固定等待秒數、連續兩次相同、刪除尾棒或人工勾選，單獨證明已收棒。
- 不補造 ask、不用後來資料回寫過去決策、不改策略或任何風控數值。
- 資料鎖只阻擋新風險；既有部位的保護、減倉與撤單走原有獨立管理路徑。
- 唯讀資料程序不持有訂單寫入能力；認證仍透過受控 Gateway 邊界。
- 恢復行情不代表帳務、時鐘、預算、每日風控、Demo 或 Live 資格通過。

## 3. 三種不同狀態

| 狀態 | 允許的用途 | 不代表什麼 |
|---|---|---|
| OBSERVED_UNVERIFIED | 保存／核對原始觀測與研究 | 不輸出可交易的 ClosedMinute |
| ACCEPTED_FOR_FEED | 在已審核證據政策下向多週期層提供資料 | 不保證永久不可修訂，也不直接允許下單 |
| RECOVERY_REQUIRED | 保留證據、停止新風險、管理既有部位 | 後續正常資料不自動解除 |

首批實作只支援第一與第三種狀態。`ACCEPTED_FOR_FEED` 是後續保留設計，
在收棒證據政策尚未核准且實作前，不得提供可啟用它的 CLI 參數或測試後門。

## 4. 證據契約

每次唯讀觀測需綁定：

1. Demo 環境、已核對商品識別、MINUTE 解析度與資料流識別。
2. 明確的 request from/to、請求前後 UTC、接收時間及時鐘誤差／不確定性。
3. 去除認證欄位的市場回應保存位置、雜湊及固定的正規化版本。
4. 原始時間標記及獨立的時間語義證據；不可直接改名為 close timestamp。
5. 品質觀測 ID、價格指紋與相對首次觀測的修訂結果。

未來的接受決策另需綁定：語義／收棒政策版本、適用環境與有效範圍、支持證據、
明確的失效条件，以及當次所需證據全部可用的 `accepted_at`。
`accepted_at` 不得早於接收完成及驗證完成；回補資料不可倒填成當時已可用。
審核政策、實際樣本與有效性檢查三者缺一，維持未驗證。
證據量與延遲門檻目前未定；未定不是零，也不能由程式猜測。

## 5. 分兩批交付

### A：離線證據核對入口（核准後先做）

新增一個無網路、無憑證、無下單能力的離線入口，讀取明確指定的本地市場回應、
固定窗口、接收時間及既有 Store，呼叫 `HistoryQualityMonitor` 並輸出白名單摘要。
不自動裁尾、不改 raw timestamp、不輸出 ClosedMinute，不清除任何鎖。

- 明確要求資料庫路徑；診斷庫標記 diagnostic，不冒充正式交易 Store。
- 傳入既有 Store 時沿用原始基準與鎖，不刪表、不覆寫首次價格。
- 記錄匯入／驗證時間；外部傳入的接收時間標為 caller-supplied，
  不能僅憑它宣稱已具備可信 PIT 來源。
- 限制輸入大小與窗口；JSON／時間格式錯誤、缺檔、寫入失敗均非成功結果。
- 同一 Store 的無法驗證輸入，能安全落盤時封鎖新倉；若資料庫失效，
  回傳明確失敗並停止呼叫鏈，不假裝持久化鎖已成功。
- 所有正常結果仍為 `entries_enabled=false`、`closure_verified=false`。
- 不把含任意額外欄位的原始 JSON 或秘密字串抄到終端及稽核事件。

### B：正式 feed 與人工恢復（需另行證據／實作審核）

待時間語義及接受政策具備證據，再接正式唯讀 adapter、ClosedMinuteBuffer 與
同一個交易 Store。所有行情讀取都必須經過品質檢查；不能保留旁路。
正式啟用前，需驗證 Guard 與資料程序共用的狀態身份，防止換資料庫避開鎖。

## 6. 恢復流程設計；A 批不實作解鎖

`偵測異常 → 持久化事件／封鎖 → 收集補證 → 建立恢復提案 → 使用者核准 → 原子復核`

恢復提案必須列明事件 ID、資料流／Store 身份、受影響窗口、原因處理證據、
政策版本、替代資料雜湊、緩衝區重建結果、broker 對帳及既有曝險的處理結果。
原因尚未釐清或其他條件不足時，可繼續診斷，但不可清鎖。

使用者核准綁定該提案內容雜湊及當前鎖版本；執行前重新檢查。若此間又有異常、
資料修訂、政策變更、提案過期或版本不同，核准失效，不能套用舊核准。
具體有效期限待 B 批規格決定，不設隱藏預設值。

只允許處理該資料鎖；操作者鎖、每日硬熔斷、未知訂單與 Live 鎖均保持獨立。
歷史事件與原始首次指紋不可刪除。若需接受修正版本，新增可追溯版本並保留舊版，
不可直接重設 `history_price_first` 或新建 DB 讓修訂看似首次觀測。
恢復失敗、崩潰或重複請求不得留下半解鎖狀態；未證實成功一律維持封鎖。

## 7. A 批離線驗收

- 正常／重複快照只觀測，不提高權限。
- 交叉、OHLC 不合法、窗口缺口、亂序、重複及價格修訂可重現並鎖定。
- 正常後值、重新建立物件、重開同一 DB 均不解除鎖。
- 缺檔、超限、JSON／時間錯誤、寫入失敗均不被誤判成通過。
- 秘密字串／任意額外欄位不進摘要；原始檔不納入 GitHub。
- 參數無法啟用已收棒、清鎖、下單或網路連線。
- 同一 Store 的新倉 Guard 尊重鎖，既有減風險路徑不因資料鎖停用。
- 既有 2026-09-21 快照作可選本地重播；可攜測試只用合成 fixture。
