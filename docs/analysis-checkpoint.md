# 分析呼叫保護與稽核摘要

日期：2026-09-20。範圍：工作包 4 的本機工程；不是 GOLD 策略驗收。

## 改變與架構

既有 `CodexFrameAnalysis` 在送出候選前，先交給 `AnalysisJournal` 預留額度；
成功取得結果後記錄摘要，失敗或取消則標為 UNKNOWN。獨立交易風控仍有最終否決權。
本輪不改 prompt、CLI 呼叫方式、策略參數或模型選擇。

| 區域 | 責任 |
|---|---|
| `analysis_journal.py` | SQLite 持久化上限、版本綁定、輸入去重與結果摘要 |
| `codex_analysis.py` | 呼叫前預留、完成／失敗登記；沿用時效與停止新倉檢查 |
| `store.py` | 保留合法整數 token 計數，其他認證 token／秘密繼續遮蔽 |

## 關鍵程式邏輯

`reserve()` 以 `BEGIN IMMEDIATE` 將查重、上限檢查與預留放進同一交易，
避免不同連線同時看見剩餘額度而超用。重啟、取消與 UNKNOWN 都不釋放已預留的次數。
程序若在登記完成前中斷，RESERVED 也繼續占用額度，不盲目重送。

同一資料庫／`budget_scope` 首次預留後固定策略、prompt 與請求模型版本；
上限或版本變更會拒絕。未指定模型的 `None` 仍表示未固定模型，
不能視為實際服務端模型身分已驗證。禁止藉自動建立新 scope 繞過預算。

輸入雜湊涵蓋 frame、候選與證據，僅對完全相同的正規化輸入去重；
候選識別／時間或行情改變會產生新雜湊，不是語義相似度去重。
新表不保存原始證據或模型原文，只保留摘要與固定版本。
`finish()` 記錄 token 整數統計與耗時，美元成本維持未知、信心維持未校準。
COMPLETED 指模型呼叫結果已登記，不代表可交易或交易成功。
